# 04. Протокол ядро ↔ воркер

Контракт — `proto/quoker/link/v1/link.proto`. Генерация — `buf generate` в `gen/`.

## Транспорт

- Воркер подключается к `w.<домен>:443` (gRPC поверх HTTP/2, TLS 1.3) с клиентским сертификатом, подписанным собственным CA проекта.
- Caddy на `w.<домен>` проверяет сертификат (`client_auth require_and_verify`) и проксирует gRPC в `core:9090` по h2c, передавая отпечаток сертификата в заголовке `X-Client-Cert-Fingerprint` и CN в `X-Client-Cert-CN`.
- Ядро дополнительно сверяет отпечаток со списком разрешённых воркеров в БД (`workers.status = allowed`). Неизвестный или отозванный отпечаток — стрим закрывается с `PERMISSION_DENIED`.
- Файлы идут отдельно от стрима, обычным HTTPS на тот же хост с тем же mTLS:
  - `PUT /internal/v1/files/{video_id}` — mp4, `Content-Range: bytes <from>-<to>/<total>` для докачки; `HEAD` возвращает уже принятый размер в `Content-Length` (`404`, если ничего не принято). Если `<from>` не совпадает с принятым размером — `416`, воркер перечитывает `HEAD` и продолжает.
  - `PUT /internal/v1/thumbs/{video_id}` — jpeg до 512 КБ.
- Запасной транспорт REALITY (см. `docs/10-deploy.md`) прозрачен для протокола: меняется только сетевой путь до ядра.

## Жизненный цикл стрима

1. Воркер открывает `Connect` и сразу шлёт `Hello`. `worker_id` обязан совпадать с CN сертификата.
2. Ядро отвечает `Config`. Повторный `Config` приходит при любом изменении (новые cookies, смена опрашивающего воркера, новый токен).
3. Обе стороны шлют `Heartbeat` каждые 15 с. Нет heartbeat 45 с — соединение считается мёртвым.
4. Ядро выдаёт `Task`, когда у воркера есть свободные слоты (`min(config.max_parallel, hello.max_parallel)` минус running).
5. Воркер шлёт `TaskProgress` не реже чем раз в `lease_ms / 3` для долгих задач — это продлевает аренду.
6. Воркер завершает задачу `TaskResult` (результат или `TaskError`).
7. `Shutdown` — ядро просит воркер завершиться (отозван, заменён). Воркер дорабатывает текущие задачи до 30 с и выходит без переподключения, если `reason = revoked`.

При обрыве воркер переподключается с экспоненциальным backoff: 1, 2, 4 … 60 с, с джиттером ±20%.

## Задачи

| Тип | Аренда | Повторы | Что делает воркер |
| --- | --- | --- | --- |
| `resolve` | 60 с | 2 | `yt-dlp -J`, обложка → `PUT /thumbs`, `ResolveResult` |
| `download` | 10 мин | 2 | Скачивание лучшего формата, `PUT /files` с докачкой, копия в tmp-кэш, `DownloadResult` |
| `send_video` | 10 мин | 1 | Файл из tmp-кэша или скачивание формата ≤ `max_bytes`, `sendVideo`, `SendVideoResult` |
| `bot_call` | 30 с | 2 | Произвольный вызов Bot API с `params_json`, `BotCallResult` |

Правила повторов: повторяются только `retryable` ошибки и истёкшие аренды; `send_video` — не более одного раза и только если Telegram не вернул `message_id` (иначе риск дубля в канале). Отмена — `CancelTask`: воркер убивает yt-dlp/загрузку и отвечает `TaskError{code: "cancelled"}`.

## Апдейты бота

- Ядро выбирает ровно одного опрашивающего воркера (`Config.poll_updates = true`); Telegram допускает одного потребителя `getUpdates` на бота (иначе 409 Conflict).
- Опрашивающий воркер: `getUpdates` с `timeout=50`, `allowed_updates = ["message", "my_chat_member", "chat_member", "callback_query"]`.
- Каждый апдейт пересылается как `BotUpdate`. Offset сдвигается только после `BotUpdateAck` от ядра — апдейты не теряются при обрыве.
- Ядро обрабатывает апдейты идемпотентно по `update_id`.
- При отключении опрашивающего воркера ядро через 30 с назначает другого (новый `Config`).

## Коды ошибок воркера

| Код | Retryable | Когда |
| --- | --- | --- |
| `unsupported_content` | нет | yt-dlp вернул фото, карусель, сторис |
| `private_video` | нет | Видео приватное, удалено, недоступно в регионе воркера |
| `login_required` | нет | Instagram требует вход, а cookies нет или не помогли (ядро сообщает админу) |
| `too_large` | нет | Нет формата до `max_bytes` |
| `rate_limited` | да | Платформа или Telegram ограничили частоту (`retry_after` учитывается ядром) |
| `target_forbidden` | нет | Telegram 403: бот не может писать в чат |
| `target_inactive` | нет | Telegram 400: чат не найден, бот исключён |
| `upstream_error` | да | Сетевые ошибки, 5xx платформы или Telegram, таймаут yt-dlp |
| `cancelled` | нет | Задача отменена |
| `internal` | да | Прочее |
