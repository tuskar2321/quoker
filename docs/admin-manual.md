# Руководство администратора Quoker

Это руководство для того, кто держит Quoker в рабочем состоянии: раздаёт приглашения, следит за воркерами, обновляет cookies Instagram и выпускает новые версии приложения. Архитектура и требования описаны в `docs/01`–`docs/12`; здесь — только то, что нужно делать руками.

> **Статус.** Ядро, воркер, бот и Android-клиент готовы. Скрипты развёртывания (`deploy/`) и CI/CD (`.github/workflows/`) ещё пишутся. Команды вида `docker compose exec core …` ниже даны для будущей схемы из `docs/10-deploy.md`. Пока её нет, те же команды запускаются бинарником ядра напрямую: `core …` с переменными окружения ядра.

## 1. Как устроена система

| Часть | Где | Что делает |
| --- | --- | --- |
| **Ядро** | VPS в РФ | API для приложения, БД (SQLite), очередь задач, кэш видео на 24 ч, логика бота, алерты |
| **Воркер** | VPS за рубежом, заменяемый | Ходит в TikTok, Instagram и Telegram: yt-dlp, `sendVideo`, `getUpdates`. Держит с ядром один gRPC-стрим по mTLS |
| **Бот** | Telegram | Привязка аккаунтов, учёт каналов и групп, команды админа, алерты |
| **Приложение** | Телефоны пользователей | Приём ссылок, скачивание в галерею, отправка в Telegram |

Главное правило: **ядро никогда не ходит во внешние сервисы само**, всё делает воркер. Если воркеров нет, приложение открывается и показывает кэш, но новые видео не скачиваются и не отправляются: задачи ждут в очереди до 10 минут, затем падают с `worker_unavailable`.

## 2. Где администрировать

Большинство действий доступны в трёх местах:

| Действие | Приложение («Настройки → Администрирование») | Бот (личка, только админ) | CLI ядра |
| --- | --- | --- | --- |
| Создать приглашение | «Приглашения → Создать» | `/invite`, `/invite admin` | `core admin bootstrap` — только первое, с ролью admin |
| Пользователи, блокировка | «Пользователи» | `/users`, `/block <id>`, `/unblock <id>` | — |
| Состояние системы | Главный экран раздела | `/status` | — |
| Cookies Instagram | «Cookies Instagram → Загрузить» | `/cookies` + файл | `core settings set instagram_cookies -` |
| Разрешить воркер | «Воркеры → Разрешить воркер» | `/allow_worker <id> <отпечаток>` | `core workers allow <id> <отпечаток>` |
| Отозвать воркер | «Воркеры → Отозвать» | `/revoke_worker <id>` | — (только сервер может сразу оборвать стрим) |
| Токен бота, прочие настройки | — | — | `core settings set <ключ> <значение\|->` |
| Выпуск APK | — | — | `core release add …`, `core release list` |

Боту нужен хотя бы один воркер на связи: сообщения в Telegram отправляет воркер. Приложению и CLI воркер не нужен — поэтому первый воркер разрешают через CLI или приложение.

## 3. Первый запуск

Подготовка серверов, DNS и сертификатов `api.<домен>` / `w.<домен>` описана в `docs/10-deploy.md`, раздел «Первое развёртывание». После того как ядро запущено:

1. **Создайте бота** у [@BotFather](https://t.me/BotFather): `/newbot`, имя и username. Сохраните токен в менеджере паролей.

2. **Передайте токен ядру.** Значение `-` читает его из stdin, чтобы токен не попал в историю shell и в список процессов:

   ```sh
   read -rs TOKEN && printf '%s' "$TOKEN" | docker compose exec -T core core settings set bot_token -
   ```

   Username бота ядро узнает само (`getMe`), как только на связи появится воркер.

3. **Выпустите сертификат первого воркера** на ПК (корневой CA хранится только там):

   ```sh
   step certificate create worker-1 worker.crt worker.key --profile leaf \
     --ca ca.crt --ca-key ca.key --not-after 8760h --no-password --insecure
   step certificate fingerprint worker.crt   # SHA-256, 64 hex-символа
   ```

   `worker-1` — это id воркера (CN сертификата). Сертификат и ключ положите на воркер в `./certs`.

4. **Разрешите воркер:**

   ```sh
   docker compose exec core core workers allow worker-1 <отпечаток>
   ```

   Отпечаток можно вставлять с двоеточиями или без, в любом регистре.

5. **Получите приглашение администратора:**

   ```sh
   docker compose exec core core admin bootstrap
   # admin invite: K7Q2-X9PL (expires 2026-11-12T10:00:00Z)
   ```

6. **Войдите в приложение** по этому коду и привяжите Telegram («Открыть бота в Telegram» → «Start»). Личка первого администратора, привязавшего Telegram, автоматически становится чатом для алертов (`admin_chat_id`).

7. **Проверьте:** в «Администрировании» воркер онлайн и «опрашивает»; отправьте боту `/status`; скачайте и отправьте себе («Сохранённое в боте») тестовое видео из TikTok и из Reels.

## 4. Приглашения

- Код формата `XXXX-XXXX`, одноразовый, действует **7 дней**.
- Роль выбирается при создании: «Пользователь» или «Администратор».
- **Код показывается один раз** — сразу скопируйте или отправьте его через «Поделиться». В списке потом видны только первые 4 символа.
- Неиспользованный код можно отозвать: «Приглашения → Отозвать».
- В боте: `/invite` — код для пользователя, `/invite admin` — для администратора.
- Регистрация ограничена: 5 попыток в час с одного IP. Если друг ошибся несколько раз подряд, пусть подождёт час.

Если пользователь вышел из аккаунта, войти снова он может только по новому приглашению.

## 5. Пользователи

- «Пользователи» в приложении или `/users` в боте: id, @username, статус, последний визит, число целей.
- **Блокировка** сразу завершает все сессии пользователя: приложение показывает «Доступ закрыт». Его цели и история сохраняются.
- **Разблокировка** возвращает сессии: пользователь продолжает работу без нового входа.
- В боте: `/block <id>`, `/unblock <id>`; id берётся из `/users`.
- Свой аккаунт заблокировать нельзя.

## 6. Воркеры и сертификаты

### Что показывает экран «Воркеры»

id, онлайн или офлайн, версии воркера и yt-dlp, срок сертификата, отметка «опрашивает» и кнопка «Отозвать». «Опрашивает» — тот воркер, который забирает апдейты бота (`getUpdates`). Он назначается автоматически: первый подключившийся, а при его отключении — следующий.

### Разрешить и отозвать

- **Разрешить:** приложение («Разрешить воркер»: id и отпечаток), бот (`/allow_worker <id> <отпечаток>`) или CLI (`core workers allow`). Повторное разрешение того же id с новым отпечатком заменяет сертификат.
- **Отозвать:** приложение или `/revoke_worker <id>`. Соединение рвётся сразу, переподключиться воркер не сможет. Чтобы вернуть его, разрешите заново. Отзыв идёт без CRL: ядро просто перестаёт принимать отпечаток.

### Срок сертификата

- Клиентский сертификат воркера выпускается на **1 год**.
- Ядро узнаёт срок при подключении воркера. Для этого Caddy передаёт сертификат в заголовке `X-Client-Cert-DER` (см. Caddyfile в `docs/10-deploy.md`). Без этого заголовка срок не показывается и алерт молчит.
- За **30 дней** до истечения строка на экране «Воркеры» становится красной, а бот раз в сутки шлёт «⚠️ Сертификат worker-1 истекает через N дн.».
- **Как обновить:** выпустите новый сертификат с тем же CN (шаг 3 первого запуска), разрешите новый отпечаток для того же id, замените файлы на воркере и перезапустите его.

## 7. Cookies Instagram

TikTok работает без входа, Instagram — не всегда. Воркер сначала пробует без cookies, а если Instagram требует вход, повторяет с cookies служебного аккаунта.

1. Заведите **отдельный служебный аккаунт** Instagram, не личный.
2. Войдите в него в браузере на ПК и выгрузите cookies в формате **Netscape** (`cookies.txt`) любым расширением для экспорта cookies. В файле должны быть cookies домена `instagram.com`; размер — до 64 КБ.
3. Загрузите файл: приложение («Cookies Instagram → Загрузить») или бот (`/cookies`, затем отправьте файл).
4. Ядро сразу рассылает новые cookies всем воркерам. Дата загрузки видна в «Администрировании».

Обновлять cookies нужно, когда бот пишет «⚠️ Instagram требует вход: обновите cookies служебного аккаунта (/cookies)», а также после переезда воркера на новый IP. Instagram может попросить подтвердить вход — подтвердите в браузере и выгрузите cookies заново.

Cookies — секрет: не храните файл в репозитории и не пересылайте его в чаты, кроме лички с ботом.

## 8. Состояние системы и алерты

### Экран «Администрирование» и `/status`

| Плитка | Что значит |
| --- | --- |
| **Воркеры** | Сколько онлайн; кто опрашивает апдейты бота |
| **Очередь** | Задачи в работе и ожидающие. Растёт очередь — воркеры не справляются или их нет |
| **Ошибки за 24 ч** | По TikTok, Reels и Telegram |
| **Диск ядра** | Заполнение диска и размер кэша видео (лимит 3 ГБ, старые файлы вытесняются сами) |

Баннер «Нет подключённых воркеров» в приложении появляется, если ни одного воркера нет на связи 5 минут.

### Алерты бота

Приходят в личку администратора (`admin_chat_id`).

| Сообщение | Что делать |
| --- | --- |
| ⚠️ Нет подключённых воркеров 5 минут | Проверить VPS воркера: жив ли сервер, контейнер, сеть. Если IP воркера заблокирован — включить REALITY (`docs/10-deploy.md`) или [заменить воркер](#11-ранбук-замена-воркера) |
| ✅ Воркер снова на связи | Ничего, проблема ушла |
| ⚠️ Воркер worker-1 не может подключиться к ядру 5 минут | Шлёт сам воркер, когда не видит ядро. Проверить ядро: открывается ли приложение, жив ли Caddy, не истёк ли сертификат `w.<домен>` |
| ⚠️ Instagram требует вход… | [Обновить cookies](#7-cookies-instagram) |
| ⚠️ Instagram: 12 из 30 запросов с ошибкой за час (код) | Смотреть код: `login_required` — cookies; `rate_limited` — Instagram режет IP воркера, переждать или сменить воркер |
| ⚠️ Диск ядра заполнен на 84% | Почистить старые бэкапы и APK в `releases/`, проверить логи Docker; при необходимости увеличить диск |
| ⚠️ Сертификат worker-1 истекает через N дн. | [Перевыпустить сертификат](#срок-сертификата) |
| 📊 Сводка за сутки | Ежедневно в 10:00 МСК: задачи, ошибки, диск, версии, активные пользователи |

## 9. Выпуск новой версии приложения

Приложение распространяется APK-файлом с ядра и само предлагает обновиться: проверяет версию при запуске не чаще раза в сутки, а также по кнопке «Проверить обновления» в настройках.

1. **Соберите подписанный APK** (позже это будет делать workflow `release-android` по тегу `app-v*`):

   ```sh
   cd android
   ./gradlew :app:assembleRelease \
     -Pquoker.versionCode=2 -Pquoker.versionName=0.2.0 \
     -Pquoker.apiBaseUrl=https://api.<домен> \
     -Pquoker.signing.storeFile=/путь/к/release.jks \
     -Pquoker.signing.storePassword=… -Pquoker.signing.keyAlias=… -Pquoker.signing.keyPassword=…
   ```

   `versionCode` должен быть больше предыдущего. Подписывайте всегда одним и тем же ключом: APK с другой подписью поверх старого не установится. Пароли удобнее передавать переменными окружения `QUOKER_SIGNING_*`, чтобы они не оставались в истории shell.

2. **Опубликуйте** — скопируйте APK в каталог релизов ядра и зарегистрируйте его. Список изменений читается из stdin:

   ```sh
   docker compose exec -T core core release add 2 0.2.0 /releases/quoker-0.2.0.apk - < changelog.txt
   docker compose exec core core release list
   ```

   Ядро проверяет, что это APK, считает SHA-256 и отклоняет занятые `version_code` и `version_name`.

3. **Обязательное обновление.** Если старые версии больше не должны работать (например, изменился API), поднимите минимальную версию:

   ```sh
   docker compose exec core core settings set min_supported_version_code 2
   ```

   Приложения с меньшим `versionCode` покажут экран «Обновите приложение» и не пустят дальше, пока не обновятся. Публикуйте релиз **до** того, как поднимаете минимум.

При первой установке обновления Android попросит разрешить установку из этого источника — это нормально.

## 10. Бэкапы

- Ядро каждый день в 04:00 МСК и перед каждой выкладкой делает снимок БД (`VACUUM INTO /backups/quoker-<дата>.db`) и хранит 7 последних.
- ПК забирает снимки скриптом `deploy/pc/backup-pull.sh` по таймеру и хранит 30, на зашифрованном диске.
- Раз в месяц на ПК проверяйте последний снимок: `sqlite3 quoker-<дата>.db 'PRAGMA integrity_check'` — должно быть `ok`.
- **Восстановление:** остановить `core`, положить снимок на место `data/quoker.db`, запустить `core`. Кэш видео восстанавливать не нужно: ядро само уберёт записи без файлов.

В БД лежат токен бота и cookies — относитесь к снимкам как к секретам.

## 11. Ранбук: замена воркера

Когда: воркер не держит стрим ни по TLS, ни по REALITY, а приложение с телефона ядро открывает — значит, заблокирован IP воркера. Цель — 30 минут от решения до приёма задач.

1. Новый VPS (Ubuntu, от 1 vCPU и 2 ГБ) в другой стране или подсети; `bootstrap.sh --role worker`.
2. На ПК — новый сертификат `worker-<N>` и его отпечаток.
3. Разрешить новый воркер (`/allow_worker` или приложение), отозвать старый (`/revoke_worker`).
4. Положить сертификат и `.env` на новый сервер, обновить `WORKER_SSH_HOST` в секретах GitHub, запустить `release-worker` на текущем теге.
5. Проверить: воркер онлайн в «Администрировании», тестовые TikTok и Reels, тестовая отправка себе.
6. Если Instagram попросил подтвердить вход с нового IP — подтвердить и [обновить cookies](#7-cookies-instagram).
7. Удалить старый VPS и его секреты.

Раз в квартал полезно прогонять замену на временном VPS с замером времени.

## 12. Частые проблемы

| Симптом | Причина и решение |
| --- | --- |
| У всех «Нет подключённых воркеров» | См. алерт про воркеры в [разделе 8](#алерты-бота) |
| Друг не может войти: «Код не подошёл» | Код истёк (7 дней), уже использован или отозван — выдайте новый. Много неудачных попыток — подождать час |
| «Ссылка устарела» при привязке Telegram | Ссылка из приложения живёт 10 минут: нажать «Открыть бота в Telegram» ещё раз |
| «Этот Telegram уже привязан к другому устройству Quoker» | Один Telegram — один аккаунт Quoker. Отвязать на старом устройстве («Настройки → Отвязать») |
| Канал или группа не появляется в «Куда отправить» | Бота должен добавить сам пользователь: в группу — участником, в канал — админом с правом публикации. Другой участник группы подключает её себе командой `/connect` в чате. Затем «Обновить список» в настройках |
| Цель серая: «Бот удалён из группы» / «Нет права публиковать» | Вернуть бота или выдать права, затем «Обновить список» |
| «Видео больше 50 МБ — в Telegram не отправить» (`too_large`) | Telegram принимает от бота до 50 МиБ, а у ролика нет формата меньше. Скачать на телефон можно — там лимит 500 МБ |
| «Слишком много запросов, попробуйте позже» (`rate_limited`) | Лимит 30 видео и 30 отправок в час на пользователя. Подождать |
| Reels не открываются, TikTok работает | Instagram требует вход — [обновить cookies](#7-cookies-instagram) |
| Приложение не видит обновление | Проверка — раз в сутки; нажать «Проверить обновления» в настройках. Проверить `core release list` |

## 13. Справочник

### CLI ядра

| Команда | Что делает |
| --- | --- |
| `core` или `core serve` | Запустить сервер |
| `core admin bootstrap` | Напечатать одноразовый инвайт администратора на 7 дней |
| `core settings set <ключ> <значение>` | Записать настройку; `-` вместо значения читает его из stdin |
| `core workers allow <id> <отпечаток>` | Разрешить сертификат воркера |
| `core release add <version_code> <version_name> <apk> [changelog\|-]` | Опубликовать APK |
| `core release list` | Список опубликованных APK |

### Ключи настроек

| Ключ | Значение | Обычно задаётся |
| --- | --- | --- |
| `bot_token` | Токен бота | Вручную, один раз (stdin) |
| `instagram_cookies` | Cookies служебного аккаунта | Через приложение или `/cookies` |
| `bot_username` | Username бота | Автоматически (`getMe`) |
| `admin_chat_id` | Чат для алертов | Автоматически: личка первого администратора |
| `poller_worker_id` | Воркер, опрашивающий апдейты | Автоматически |
| `min_supported_version_code` | Минимальная поддерживаемая версия приложения | Вручную при обязательном обновлении |

Смена токена бота или cookies рассылается воркерам без перезапуска.

### Команды бота для администратора

Работают только в личке с ботом и только для `role = admin`.

| Команда | Действие |
| --- | --- |
| `/invite`, `/invite admin` | Приглашение на 7 дней |
| `/users` | Пользователи |
| `/block <id>`, `/unblock <id>` | Блокировка и разблокировка |
| `/status` | Воркеры, очередь, ошибки за 24 ч, диск, версии |
| `/cookies` + файл | Обновить cookies Instagram |
| `/workers` | Воркеры |
