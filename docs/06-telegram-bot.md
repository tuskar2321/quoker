# 06. Telegram-бот

Один бот на всех пользователей. Токен хранится в ядре (`settings.bot_token`), сетевые вызовы делает воркер; вся логика — в ядре (`internal/core/bot`). Исходящие сообщения бота — задачи `bot_call`.

## Привязка аккаунта

1. Приложение: `POST /v1/auth/telegram/link` → ядро создаёт токен (32 байта, base64url), хранит SHA-256, TTL 10 минут, отдаёт `https://t.me/<bot_username>?start=link_<token>`.
2. Пользователь жмёт «Start» → апдейт `message` с текстом `/start link_<token>` в личке.
3. Ядро проверяет токен:
   - валиден → `users.tg_user_id = from.id`, username, first_name; создаёт цель `private` (личка с ботом, «Сохранённое в боте»); отвечает «Готово! Quoker привязан к @username. Теперь добавьте меня в канал или группу, куда хотите отправлять видео.» с инструкцией;
   - этот `tg_user_id` уже привязан к другому аккаунту → «Этот Telegram уже привязан к другому устройству Quoker. Отвяжите его там или обратитесь к администратору.»;
   - истёк или использован → «Ссылка устарела. Откройте Quoker и нажмите „Привязать Telegram“ ещё раз.»
4. Приложение опрашивает `GET /v1/auth/telegram/status` раз в 2 с, пока открыт экран привязки.

`/start` без токена или от непривязанного пользователя → «Это бот приложения Quoker. Он работает только вместе с приложением по приглашению.»

## Цели: учёт по `my_chat_member`

| Событие | Условие | Действие ядра |
| --- | --- | --- |
| Бот добавлен в группу/супергруппу | `from.id` привязан | Цель `group` для этого пользователя; сообщение в группу: «Привет! @username может отправлять сюда видео из Quoker. Другим участникам — команда /connect.» |
| Бот добавлен в группу | `from.id` не привязан | Сообщение «Чтобы отправлять сюда видео, сначала привяжите Quoker к своему Telegram, затем отправьте /connect» |
| Бот стал админом канала с `can_post_messages` | `from.id` привязан | Цель `channel` для этого пользователя (в канал бот ничего не пишет) |
| Бот стал админом канала без права публикации | — | Цель (если есть) → `inactive: bot_not_admin`; пользователю в личку: «В канале „<title>“ у меня нет права публиковать сообщения.» |
| Бот удалён из чата / разжалован в канале | — | Все цели этого `chat_id` → `inactive: bot_removed` / `bot_not_admin` |
| Миграция группы в супергруппу | `migrate_to_chat_id` | Обновить `chat_id` у всех целей |
| Смена названия чата | `new_chat_title` | Обновить `title` |

`/connect` в группе: проверить, что отправитель привязан и является участником (для группы) — создать цель для него; ответ реплаем «Готово, „<title>“ появится в Quoker у @username». В каналах команд нет: подключить канал может только админ канала, повысивший бота, или другой админ через приложение (`POST /v1/targets/refresh` перепроверяет каналы, где бот админ, через `getChatMember` для пользователя).

## Проверка прав перед отправкой

- Для группы: `getChatMember(chat_id, user.tg_user_id)` — статус `creator | administrator | member | restricted (с can_send_media)`.
- Для канала: `creator | administrator` с `can_post_messages`.
- Результат кэшируется в `targets.rights_checked_at` на 5 минут. Нет прав → цель `inactive: user_left | user_not_admin`, отправка `403 target_forbidden`.
- Бот больше не видит чат (`chat not found`, бот исключён) → все цели чата `inactive: bot_removed`, отправка `409 target_inactive`.
- Воркер не ответил на `getChatMember` за время запроса → отправка не блокируется: окончательное слово за Telegram, его 403 при `sendVideo` тоже деактивирует цель.

## Подпись к видео

Ядро собирает `caption_html` (parse_mode HTML, экранирование `& < >`):

1. Текст пользователя (по умолчанию — `canonical_url`), обрезка до 1024 символов с учётом пункта 2.
2. Только для `group` и `sign_as_user = true`: новая строка + `от @username`, или `от <first_name>`, если username нет.
3. Пустая подпись — без `caption`.

## Отправка видео (воркер)

`sendVideo` multipart: `chat_id`, `video` (файл), `caption`, `parse_mode=HTML`, `supports_streaming=true`, `duration`, `width`, `height`, `thumbnail` (jpeg ≤ 200 КБ, 320 px), `disable_notification=false`. Ответ 429 → `rate_limited` с `retry_after`; 403 → `target_forbidden`; 400 «chat not found» → `target_inactive`.

## Команды администратора (только в личке, только `role = admin`)

| Команда | Действие |
| --- | --- |
| `/invite` | Создать инвайт-код на 7 дней, прислать код |
| `/invite admin` | То же с ролью admin |
| `/users` | Список пользователей: id, @username, статус, последний визит |
| `/block <id>`, `/unblock <id>` | Блокировка / разблокировка |
| `/status` | Воркеры, очередь, ошибки за 24 ч, диск, версии |
| `/cookies` + файл `cookies.txt` | Обновить cookies Instagram, разослать новый `Config` |
| `/workers` | Список воркеров |
| `/allow_worker <id> <fingerprint>` | Разрешить воркер |
| `/revoke_worker <id>` | Отозвать воркер |

Команды регистрируются через `setMyCommands` со scope `chat` для админа, `all_private_chats` (только `/start`, `/help`) для остальных и `all_group_chats` (`/connect`). Регистрация и `getMe` (сохраняет `bot_username`) выполняются при старте ядра, как только воркер с токеном на связи, и при привязке администратора. `admin_chat_id` для алертов — личка первого администратора, привязавшего Telegram. `/cookies` принимает файл до 64 КБ с cookies домена `instagram.com`.

## Алерты и сводка

Тексты коротко и по делу, с эмодзи-маркером в начале: «⚠️ Нет подключённых воркеров 5 минут», «⚠️ Instagram: 12 из 30 запросов с ошибкой за час (login_required)», «⚠️ Диск ядра заполнен на 84%», «⚠️ Сертификат worker-1 истекает через 30 дней», ежедневная сводка в 10:00 МСК: задачи, ошибки по платформам, диск, версии, активные пользователи.
