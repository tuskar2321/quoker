# 11. Нефункциональные требования и безопасность

## Производительность

| Метрика | Цель |
| --- | --- |
| Открытие sheet из «Поделиться» (холодный старт) | ≤ 1,5 с до скелетона |
| Превью видео | ≤ 3 с из кэша ядра, ≤ 8 с без кэша (p90) |
| Отправка в Telegram после нажатия | ≤ 15 с для ролика до 30 МБ при уже скачанном файле на воркере |
| Скачивание на телефон | Ограничено сетью телефона ↔ ядро; без лишних копий на телефоне |
| Потребление ядра | ≤ 512 МБ RAM при 20 пользователях |

## Надёжность

- Задачи переживают переподключение и замену воркера (аренды и повторы, `docs/04-core-worker-protocol.md`).
- Отправка не дублирует сообщение в канале: повтор `send_video` только если Telegram не подтвердил отправку.
- Апдейты бота не теряются: offset сдвигается после ack ядра; обработка идемпотентна.
- Ядро стартует с повреждённым кэшем: сироты удаляются, записи без файлов переводятся в `file_status = none`.
- Graceful shutdown: ядро дожидается текущих HTTP-ответов и закрывает стримы с `Shutdown` (до 20 с), воркер доделывает задачи (до 30 с).

## Безопасность

- Весь внешний трафик — TLS 1.2+ (публичный API), TLS 1.3 + mTLS (воркеры).
- Сессионные токены и токены привязки — 32 байта из `crypto/rand`, в БД только SHA-256; поиск идёт по хэшу, поэтому сравнение не зависит от совпадающего префикса.
- Коды инвайтов — `XXXX-XXXX` из `crypto/rand` по алфавиту из 32 символов без похожих `0/O` и `1/I` (≈40 бит); от перебора защищают лимит регистраций 5 в час на IP (каждая попытка), одноразовость и срок 7 дней. В БД — SHA-256 кода и первые 4 символа для списка.
- На устройстве `session_token` зашифрован ключом из Android Keystore.
- Каждый запрос к цели проверяет владельца (`owner_user_id = текущий пользователь`); ID в API не дают доступа к чужим данным — проверки на уровне сервисов, а не только роутера.
- Права в Telegram-чате перепроверяются не реже раза в 5 минут перед отправкой.
- Админ-эндпоинты и команды бота — только `role = admin`; команды бота — только в личке.
- Секреты (токен бота, cookies, ключи) не пишутся в логи; в логах `tg_user_id` и `chat_id` допустимы, тексты подписей — нет.
- Входные данные: URL до 2048 символов, подпись до 1024, cookies до 64 КБ; тела запросов ограничены 1 МБ (кроме загрузки файлов воркером).
- yt-dlp запускается без shell, аргументы — массивом; URL перед передачей проходит нормализацию и белый список доменов.
- Файлы от воркеров принимаются только по mTLS, имя файла вычисляется ядром из `video_id`, а не берётся из запроса.
- APK проверяется по `sha256` перед установкой.
- Контейнеры — от непривилегированного пользователя, `read_only: true` где возможно, `no-new-privileges`.

## Приватность

- Ядро хранит: Telegram id, username, имя, цели, историю за 90 дней, метаданные видео. Сами видео — не дольше 24 ч после последнего обращения.
- Никакой сторонней аналитики и крэш-репортинга. Падения клиента пишутся в локальный лог, который пользователь может отправить админу вручную из настроек («Отправить отчёт» → share-intent с файлом).

## Лимиты

| Что | Значение |
| --- | --- |
| Резолв | 30 / час / пользователь |
| Отправка | 30 / час / пользователь |
| Регистрация | 5 / час / IP |
| Параллельных задач на воркере | 2 |
| Размер для отправки в Telegram | 50 МиБ |
| Размер для скачивания на телефон | 500 МБ |
| Кэш файлов ядра | 3 ГБ |
| Временный кэш воркера | 1 ГБ |
| Длительность ролика | до 10 минут; дольше — `unsupported_content` |

## Наблюдаемость

- Логи — JSON (`slog`), поля: `ts`, `level`, `msg`, `component`, `request_id`, `task_id`, `user_id`, `worker_id`, `video_id`, `error_code`.
- Метрики (`/metrics`, Prometheus-формат) на внутреннем порту ядра `8081`, только для `TRUSTED_PROXIES` (наружу Caddy его не пропускает): `quoker_task_duration_seconds{kind,platform}` — от постановки до успешного результата, `quoker_task_errors_total{kind,code}`, `quoker_queue_tasks{kind,status}`, `quoker_workers_connected`, `quoker_cache_bytes`, `quoker_cache_limit_bytes`, `quoker_http_responses_total{code}`.
- `/healthz` — живость процесса; `/readyz` — БД доступна, миграции применены.

## Совместимость

- Android 8.0+ (API 26); проверять на API 26, 29, 33 и последней.
- Публичный API версионируется префиксом `/v1`; несовместимые изменения — только с поднятием `min_supported_version_code`.
- Proto — только обратносовместимые изменения (`buf breaking` в CI); ядро обновляется раньше воркера.
