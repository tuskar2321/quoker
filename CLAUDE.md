# Quoker — инструкции для Claude Code

Quoker — личное Android-приложение: принимает ссылку на видео TikTok или Instagram Reels (через меню «Поделиться» или вставкой), скачивает его в галерею и/или отправляет через Telegram-бота в выбранный чат или канал. Пользователи — владелец (Max, администратор) и небольшой круг друзей по приглашениям.

Это полное описание продукта, а не MVP: реализуем всё, что описано в `docs/`. Порядок работы задаёт владелец в каждой сессии.

## Структура репозитория

```
quoker/
  CLAUDE.md
  docs/                 спецификация (источник правды)
  api/openapi.yaml      публичный API ядра
  proto/                контракт ядро ↔ воркер (buf)
  gen/                  сгенерированный Go-код из proto (не править руками)
  cmd/core/             main ядра
  cmd/worker/           main воркера
  internal/core/...     пакеты ядра
  internal/worker/...   пакеты воркера
  internal/shared/...   общее: url-нормализация, ошибки, логирование
  core/migrations/      SQL-миграции SQLite
  android/              Android-проект (Gradle, app.quoker)
  deploy/               bootstrap.sh, compose-файлы, Caddyfile, шаблоны xray
  .github/workflows/    CI/CD
```

Go — один модуль в корне: `github.com/tuskar2321/quoker`.

## Команды

Создай `Makefile` с целями и поддерживай его в рабочем состоянии:

- `make gen` — `buf generate` для proto
- `make test` — `go test ./...` с `-race`
- `make lint` — `golangci-lint run`
- `make run-core`, `make run-worker` — локальный запуск с `.env.local`
- `make dev` — docker compose для локальной разработки: ядро + воркер + фейковый Telegram API
- `cd android && ./gradlew assembleDebug testDebugUnitTest`

## Правила работы

- **Git.** Никогда не выполняй `git commit`, `git push`, удаление веток на remote. Готовь изменения и давай текст команды владельцу. Остальные команды git (status, diff, log, add, checkout -b) — можно.
- **Сообщения коммитов** предлагай короткими, по-английски, в повелительном наклонении. Никаких строк атрибуции («Generated with Claude Code», `Co-Authored-By: Claude` и т. п.).
- **Язык.** Код, комментарии, идентификаторы, логи — по-английски. Тексты интерфейса — по-русски, только через ресурсы (`strings.xml`), см. `docs/08-android.md`. Документация — по-русски.
- **Секреты** (токен бота, cookies Instagram, ключи, сертификаты) никогда не попадают в репозиторий, логи и тестовые фикстуры. В репозитории — только `.env.example`.
- **Документация — источник правды.** Если по ходу работы решение меняется, сначала согласуй с владельцем, потом обнови соответствующий файл в `docs/` в том же изменении.

## Соглашения Go

- Go последней стабильной версии; стандартная библиотека в приоритете. Роутер — `chi`, gRPC — `google.golang.org/grpc`, SQLite — `modernc.org/sqlite` (без CGO), миграции — встроенные через `embed`, логирование — `log/slog` в JSON.
- Все внешние вызовы и запросы к БД принимают `context.Context` и имеют таймауты.
- Ошибки оборачиваются через `fmt.Errorf("...: %w", err)`; доменные ошибки — типизированные коды из `docs/03-public-api.md`.
- Никаких глобальных переменных состояния; зависимости передаются через конструкторы.
- Тесты табличные; внешние системы (Telegram, yt-dlp, воркер) подменяются фейками, а не моками на уровне функций.
- `panic` только для ошибок программиста при старте.

## Соглашения Android

- Kotlin, Jetpack Compose, Material 3, Hilt, Retrofit + OkHttp + kotlinx.serialization, Coroutines/Flow, WorkManager, DataStore, Room, Coil 3, Navigation Compose.
- Архитектура: MVVM с однонаправленным потоком данных (`UiState` + события), модули по фичам (см. `docs/08-android.md`).
- Цвета, размеры и типографика — только из темы `core:designsystem`, значения из `docs/09-design.md`. Хардкод цветов в экранах запрещён.
- Все строки — в `strings.xml`; плюрализация через `plurals`.

## Чего не делать без согласования

- Менять публичный API, proto-контракт или схему БД несовместимо.
- Добавлять зависимости тяжелее пары сотен КБ или со своим нативным кодом.
- Вводить новые внешние сервисы (аналитика, крэш-репортинг, облака).
- Переносить логику из ядра в воркер или наоборот: разделение описано в `docs/02-architecture.md` и важно для обхода блокировок.
